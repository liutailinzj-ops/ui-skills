# Company Library Promotion Policy

Do not design a speculative company library before real project evidence exists.

## Promotion candidate

Consider promotion after the component:

- Appears in at least 3 real projects or has a clearly universal web role.
- Uses a stable property API across those projects.
- Uses compatible semantic tokens.
- Has documented Desktop/Mobile behavior.
- Can be maintained without forcing unrelated brand styles into one component.

## Keep local when

- The component expresses a unique brand or campaign idea.
- The API changes materially between projects.
- The component depends on one theme's specific structure.
- Promotion would create excessive variants or overrides.

Review promotion candidates after 3–5 pilot projects, then create an `IWISH Web Core` library from verified patterns.
