# 内容与整页构图验收

本检查在代表 Section 之后、结构 QA 之前进行。局部模块好看不能覆盖内容空泛或完整页面表现一般。

## 内容检查

- 产品、品类、市场、用户问题和竞品呈现逻辑是否真实进入页面内容。
- 每个 Section 是否有唯一访客问题、产品相关角度、媒体任务和下一步。
- 是否存在三段以上可用于无关产品的通用生活方式文案。
- 是否重复同一卖点来填充 Hero、Benefits、Steps、Story、CTA 和 FAQ。
- 指定竞品模块是否保留内容、媒体、交互和转化关系，而不是只保留标题主题。
- 客户预览是否出现 `placeholder`、`pending`、`review concept`、确认、批准、验证、替换或内部流程语言。

## 整页构图检查

- Section 是否共享一个明确栅格和命名容器模式。
- 首屏、主要转化点和决策关键媒体是否有清晰权重。
- 色彩、图片、文字密度和留白是否形成有意图的完整页面曲线。
- 是否连续重复 split、三卡、编号、深浅交替、FAQ/CTA 收尾等固定节奏。
- 代表 Section 是否真正属于同一页面，而不是多个单独好看的模块拼接。
- 纯自定义页面是否形成独立创意命题，而不只是干净、对齐和使用真实图片。
- UI 是否可以保留主要顺序、栅格和构图继续微调；若仍需重做首屏或大部分 Section，判失败。

## 结果

- `通过`：内容和完整页面均达到 UI 可继续微调的初稿水平。
- `需要调整`：方向成立且问题可由少量明确局部修改解决。
- `失败`：内容空泛、整页一般、固定模板感明显、客户预览泄漏内部状态，或 UI 需要重新做大部分页面。
