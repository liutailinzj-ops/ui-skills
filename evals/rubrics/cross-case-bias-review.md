# 跨案例审美偏差检查

本检查用于识别 Skill 自己带来的固定审美，不属于 UI 日常生产流程，不写入生产项目 Manifest 或客户 Figma。

## 使用条件

- 同一项 Skill 改动已经在至少两个互不复用项目状态的就绪案例中生成可视结果。
- 每个案例从自己的客户输入、研究证据、主题能力、视觉方向契约和空白或隔离的 Figma 测试空间开始；不得复制其他案例的节点、变量、样式或代表性模块。
- 先完成各案例的 `technical-visual-review.md`，再做本检查。单个案例无法证明不存在跨案例偏差。

## 建立签名

为每个案例记录截图证据和以下项目专属签名：

1. 主色、强调色、背景/文字角色及关键色值。
2. 字体家族、字重关系和 Display/Heading/Body 层级。
3. 首屏拓扑、媒体与内容比例、主要对齐逻辑。
4. Section 顺序、长页密度、留白和节奏。
5. 卡片、按钮、圆角、边框、阴影和数据展示语法。
6. 图片主体、环境、光线、裁切和产品尺度。
7. 交互或动效姿态，仅在项目确实要求时记录。

同时记录每个签名字段的依据：客户品牌、指定结构、视觉参考、竞品/品类研究、目标主题、项目创意决策或无依据。

## 判定

- 共享的可编辑性、语义变量、响应式配对、无障碍底线、命名和 QA 规则不是审美偏差。
- 相似行业或共享主题可以产生部分相似结构，但必须能追溯到共同证据。
- 若无共同输入证据，却在两个及以上无关案例中重复完全相同的品牌性字段，例如相同强调色值、相同字体组合或高度特征化的首屏构图，判定 `skill_induced_visual_bias`。
- 若无共同输入证据，且七类签名中至少三类呈现相同或近似的固定组合，判定 `skill_induced_visual_bias`；不能用“常见做法”替代证据。
- 单一常见组件、一个中性色或一个基础间距值相同，不足以单独判失败。
- 发现偏差后，修正产生该默认值的通用规则或候选选择逻辑，不得为某个测试品牌写例外。
